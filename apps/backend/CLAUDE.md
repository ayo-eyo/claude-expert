## Commands

Run from `apps/backend/` (or append `-w backend` when running from the repo root):

```bash
npm run start        # nest start
npm run start:dev    # nest start --watch (port 4000)
npm run start:debug  # nest start --debug --watch
npm run start:prod   # node dist/main (run `build` first)
npm run build        # nest build
npm run lint         # eslint --fix over src/apps/libs/test
npm run test         # jest (unit tests, *.spec.ts, rootDir: src)
npm run test:watch   # jest --watch
npm run test:cov     # jest --coverage
npm run test:e2e     # jest --config ./test/jest-e2e.json
```

Single test file: `npx jest src/app.controller.spec.ts` (or `npx jest -t "<test name>"` to filter by name). For e2e: `npx jest --config ./test/jest-e2e.json test/app.e2e-spec.ts`.

## Architecture

Standard NestJS module structure, generated by `@nestjs/cli`:

- `src/main.ts` — bootstraps the app with `NestFactory.create`, enables CORS (`app.enableCors()`), and listens on `process.env.PORT ?? 4000`. CORS is on because the Next.js frontend (port 3000) calls this API directly.
- `src/app.module.ts` — root module; register new feature modules here as they're added.
- `src/app.controller.ts` / `src/app.service.ts` — the default controller/service pair from the generator; replace/extend as real endpoints are built.
- `test/` — e2e tests, run against a full Nest application instance via `jest-e2e.json`.

There is no database, auth, or additional module wired up yet — this is the unmodified Nest CLI scaffold plus the port/CORS change above.
