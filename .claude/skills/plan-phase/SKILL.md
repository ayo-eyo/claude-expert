# Plan Generator

Прочитай PDR из файла: $ARGUMENTS

Сохрани план реализации в в 'docs/plan-$ARGUMENTS.md', используй перевод на английский и kebab-case

## Структура плана

# Plan: {название фичи}

**PRD**: {ARGUMENTS}
**Дата**: {Текущая дата}

## Фазы реализации

### Фаза 1: {название}

**Цель**: Что дает эта фаза
**Затрагиает**: backend/frontend/database/etc.
**Задачи:**:

- [ ] Задача 1
- [ ] Задача 2
      **Когда готова**: Конкретный критерий

### Фаза 2: {название}

...

## Правила разбивки на фазы:

- Каждая фаза должна давать рабочий результат
- Фазы независимы, можно оставиться после любой
- Первая фаза как минимальный рабочий путь (tracer bullet)
- Не более пяти задач в одной фазе
- backend и frontend одной фичи в разных фазах
- В каждой фазе должны быть тесты для покрытия функциональноси фазы

## Правила

- Читай PRD внимательно, план должен покрывать все критерии готовности
- Не добавляй задачи, которых нет в PRD
- Если PRD не полный, задай вопрос перед выполнением плана
